# Deploying Risk Management on Vercel

This repository is a **Laravel application with a Vite frontend**, not a static Vite-only site. The `vercel.json` and `api/index.php` files route web requests to a PHP serverless function while serving built assets from `public/`.

## Vercel Project Settings

| Setting | Required value |
|---|---|
| Framework Preset | `Other` |
| Build Command | `npm run build` |
| Output Directory | Leave **empty**. Do not set `dist`. |
| Install Command | Leave the default installation command unless the project configuration requires an override. |
| Root Directory | Repository root |

> Do not configure `dist` as the output directory. Vite writes this project’s manifest and assets to `public/build`, while the Laravel application itself must execute through the PHP serverless entrypoint.

## Required Environment Variables

Set these in **Production**, and also in Preview if you want preview deployments to be functional. Never commit any secret value.

| Variable | Purpose |
|---|---|
| `APP_KEY` | A Laravel application key, for example a value generated by `php artisan key:generate --show`. |
| `APP_URL` | The HTTPS Vercel deployment URL or custom domain. |
| `DB_CONNECTION` | `mysql` or another externally hosted database driver. |
| `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | Managed database connection credentials. |
| `SESSION_DRIVER` | A persistent backend such as `redis`. Do not use file sessions on serverless instances. |
| `CACHE_DRIVER` | A persistent backend such as `redis`. |
| `QUEUE_CONNECTION` | A persistent queue backend when queued work is enabled. |
| `FILESYSTEM_DRIVER` | `s3` for evidence attachments and uploaded files. |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `AWS_BUCKET` | Persistent object-storage credentials when `FILESYSTEM_DRIVER=s3`. |
| `MAIL_*` | SMTP or transactional email provider configuration for notifications and scheduled reports. |

The repository’s `vercel.json` already sets production-safe non-secret defaults: `APP_ENV=production`, `APP_DEBUG=false`, `LOG_CHANNEL=stderr`, and temporary locations under `/tmp` for generated framework caches and compiled views.

## Before the First Deployment

Run migrations against the managed production database from a trusted CI job, a release process, or a controlled administrator machine. Do not run destructive migration commands from an arbitrary Vercel request.

```bash
php artisan migrate --force
```

The application uses scheduled workflows and external integrations. Configure a production-safe scheduler/queue worker separately; Vercel function instances are request-driven and have ephemeral local storage.

## Serverless Constraints

Laravel requests can run through the supplied PHP runtime, but the platform is not a replacement for a long-running worker. Keep database, session, cache, queue, and file storage external and persistent. Place uploads in object storage, send logs to the platform log stream or an external log provider, and run backups/restore drills from the operational process rather than the Vercel filesystem.

## Troubleshooting

| Symptom | Resolution |
|---|---|
| `No Output Directory named dist` | Clear the Vercel Output Directory setting. This project uses `vercel.json`; it is not a `dist` static-site deployment. |
| The build succeeds but pages return a server error | Check `APP_KEY`, database credentials, `APP_URL`, and the Vercel function logs. |
| Login works inconsistently between requests | Move `SESSION_DRIVER` and `CACHE_DRIVER` to Redis or another persistent service. |
| Attachments disappear | Set `FILESYSTEM_DRIVER=s3` and configure the bucket credentials. |
| Scheduled reports or background refreshes do not run | Run the scheduler and queue through a separate persistent service or an external scheduler that invokes the intended command safely. |
